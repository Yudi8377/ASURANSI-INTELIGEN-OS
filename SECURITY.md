# Security Policy

## Reporting
Please do not publish exploit details or customer data in public issues. Report suspected vulnerabilities privately to the repository owner through GitHub's private vulnerability reporting feature if enabled, or contact the repository maintainer through a verified channel.

## Scope and authorization
Only test systems and accounts you own or have explicit written authorization to assess. No social engineering, denial-of-service, data exfiltration, persistence, or testing against third-party systems.

## Response expectations
Maintainers should acknowledge a report, reproduce it in a controlled environment, assess severity, prepare a fix, and coordinate disclosure. Do not include secrets, production personal data, or live credentials in reports.

This policy is a starting point and does not imply an active bug bounty program or a guaranteed response SLA.
